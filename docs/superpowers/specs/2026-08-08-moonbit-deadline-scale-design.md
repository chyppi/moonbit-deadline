# moonbit-deadline 4K 源码规模扩展设计

## 目标

在不改变现有核心 API 语义的前提下，把项目扩展到约 4,000–4,400 行有效 `.mbt` 源码。规模增长必须来自可复用的期限领域能力、清晰的边界和对应测试，而不是重复实现、无意义的数据填充或只增加注释。

当前基线约为 1,286 行 `.mbt` 源码（实现与测试），生成的 `.mbti` 不计入目标规模。扩展后仍保持单一根包和现有 CLI 入口，避免引入不必要的发布与依赖复杂度。

## 不变的兼容性约束

- `Date`、`DateRule`、`Deadline`、`Calendar`、`ExtensionPolicy` 和现有 CLI 基本用法继续可用。
- 日期计算保持确定性；所有节假日和调休数据仍由调用方注入或通过明确标注来源的 fixture 提供。
- 不提供法律意见，不把某个法域的规则硬编码为全球默认行为。
- 计算错误继续通过结构化错误返回，禁止静默生成无效日期。
- 新模块只依赖现有根包类型，不引入第三方运行时依赖。

## 领域模块

### 1. 日期区间

新增 `DateRange` 和相关操作：

- 构造闭区间、半开区间和单日区间
- 验证起止顺序
- `contains`、`overlaps`、`intersection`、`union` 的确定性语义
- 日历日、工作日和指定日规则下的区间计数
- 受边界保护的日期枚举

区间统一使用已有 `Date`，不会复制另一套日期算法。空区间、相邻区间和跨年区间要有明确测试。

### 2. 多阶段期限计划

新增 `DeadlinePlan`、`PlanStage` 和阶段结果：

- 每个阶段绑定一个 `DateRule`、起算策略、日历和顺延策略
- 阶段可以以上一阶段的原始届满日或调整后届满日作为下一阶段起点，默认使用调整后日期
- 支持阶段标签、阶段级说明和最终摘要
- 任一阶段失败时返回带阶段索引和阶段标签的结构化错误

现有 `Deadline::calculate` 作为单阶段快捷入口，内部可复用计划引擎但不要求调用方迁移。

### 3. 暂停、恢复和中止

新增 `SuspensionPeriod`、`SuspensionPolicy` 与期限暂停计算：

- 暂停区间包含起止日期，并验证区间有效性
- 支持暂停日计入、暂停日排除两种明确策略
- 多个暂停区间先排序并合并重叠/相邻区间，避免重复延长
- 支持恢复事件和中止错误；中止不会返回伪造的届满日
- 只对配置明确允许暂停的阶段生效，普通 `Deadline` 行为不变

该模块只处理日期级暂停，不引入时区、时刻或送达时间模型。

### 4. 事件时间线与审计轨迹

新增 `DeadlineEvent`、`EventTimeline` 和事件结果：

- 事件类型包括起算、阶段开始、暂停、恢复、阶段届满、最终届满和错误
- 时间线保留事件顺序、来源标签、日期和对结果的影响
- 事件排序采用日期、优先级和声明顺序的稳定规则
- 对外提供只读访问器，不暴露可破坏内部不变量的可变集合
- 现有 `CalculationStep` 和 `DeadlineResult` 可以转换为时间线事件

时间线是解释输出和未来 JSON/表格输出的共同数据源，避免 CLI 自己重复计算。

### 5. 版本化日历与观察日

新增 `CalendarVersion`、`CalendarSource` 和观察日策略：

- 记录日历名称、地区、版本、来源和适用日期范围
- 支持基于已有 `Calendar` 叠加观察日、固定周末和额外工作日
- 明确节假日冲突优先级：额外工作日覆盖节假日，节假日覆盖周末
- 对 2026 中国示例日历增加版本元数据和来源校验测试
- 不把来源说明当作运行时法律判断，文档继续保留生产使用边界

### 6. 报告和 CLI 输出

新增 `DeadlineReport`：

- 输出起算日、规则、日历版本、阶段结果、暂停区间、最终届满日和警告
- 支持稳定的纯文本、表格和机器可读键值输出
- 输出字段顺序固定，日期统一 ISO-8601
- 对空结果、错误结果和多阶段结果提供可读解释

CLI 增加计划和报告选项，但保留当前单规则命令格式。参数错误继续返回非零退出码，并打印最小可用帮助。

## 文件组织

新增文件按职责拆分，建议包括：

- `date_range_types.mbt`、`date_range_logic.mbt`、`date_range_test.mbt`
- `plan_types.mbt`、`plan_engine.mbt`、`plan_test.mbt`
- `suspension_types.mbt`、`suspension_logic.mbt`、`suspension_test.mbt`
- `timeline_types.mbt`、`timeline_logic.mbt`、`timeline_test.mbt`
- `calendar_version_types.mbt`、`calendar_version_logic.mbt`、`calendar_version_test.mbt`
- `report_types.mbt`、`report_render.mbt`、`report_test.mbt`
- `cli_plan.mbt`、`cli_report.mbt` 及对应 CLI 规格测试

实际文件名可在实现阶段根据 MoonBit 包接口和生成的 `.mbti` 调整，但每个文件只承担一个清晰职责。

## 测试策略

所有新增行为遵循 RED–GREEN–REFACTOR：

1. 先写一个最小失败测试，确认失败原因是缺少目标行为。
2. 写能通过该测试的最小实现。
3. 运行根包和 CLI 的全套测试，再进行小范围重构。

测试覆盖：

- 区间边界、相邻/重叠区间、跨月、跨年和闰年
- 计划阶段起点选择、阶段失败定位、零阶段和单阶段兼容
- 暂停区间合并、端点策略、恢复、中止和重复暂停
- 事件排序稳定性、来源标签和最终摘要
- 日历版本元数据、观察日冲突优先级和来源 fixture
- 报告字段顺序、空值、错误和多阶段输出
- CLI 参数组合、帮助、错误退出码和确定性输出

目标是在扩容后维持所有目标的 `moon check --deny-warn`、`moon test --deny-warn` 和 `moon build` 通过；CI 继续覆盖 Linux、macOS、Windows。

## 规模控制

扩展目标为约 4,000–4,400 行 `.mbt`，按以下方式控制质量：

- 约一半新增行来自可复用实现和访问器，约一半来自行为测试、CLI 测试和边界用例。
- 不复制已有日期算法，不为行数增加无调用方的 public API。
- 每个新增 public 类型必须有至少一个 README/API 文档示例或明确的 API 文档条目。
- 每个新增 public 行为必须有测试；复杂错误必须有错误路径测试。
- 生成的 `.mbti`、构建产物和临时文件不计入规模，也不提交到仓库。

## 交付验收

- `.mbt` 有效源码达到约 4,000 行，且规模统计排除生成 `.mbti`。
- 现有测试和新增测试在 wasm、wasm-gc、js、native 四个目标通过。
- CLI 单规则命令保持兼容，计划/报告命令有成功和失败测试。
- README、`docs/api.md`、`docs/calendar-data.md` 和 `CHANGELOG.md` 记录新增能力与边界。
- Git 历史保持单一 `chyppi` 作者身份，GitHub 与 GitLink 的 `main`/`master` 远程状态不被扩容改动破坏。
- CI、格式化、信息生成和工作区差异检查通过后，才更新提交审计记录。
